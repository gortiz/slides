You cannot beat physics

  • The less you copy, the slower the query: one line
  • External Tables + indexes: much faster, only the indexes are local
  • Every byte a query needs still has to move

You cannot always use indexes

  • Two questions: indexes created? Can this query use them?
  • Any "no": a scan like any engine
  • Indexes are optional

Write Iceberg for its readers

  • Sort by the filter key
  • Sane file and row-group sizes
  • v3 deletion vectors
  • Compact on a schedule
  • Sort or cluster by the filter key
  • Deletion vector (v3) = per-file bitmap of deleted rows
  • Pinot applies only v3 deletion vectors
  • Comcast: −35–40% scanned data by sorting on device ID

Configure Pinot for your queries

  • Index what you filter on
  • Star-tree for dashboards
  • Size the cache
  • Same region as the bucket
  • Each index: one read of its column per segment + storage on S3
  • Keep data and cluster in the same region: ranged reads are region-strict
