CHAPTER 2 Pinot Analytics as a product feature

Why Pinot exists

  • "Who viewed your profile"
  • Analytics for every user
  • Thousands of queries per second
  • Milliseconds, not seconds
A warehouse serves a few analysts. Pinot serves every user of the product, so concurrency and tail latency come first. Tie back to plays: "your week in music" is the same shape of problem.

The moving parts

  • Controller: metadata, assignment
  • Broker: plans, routes, merges
  • Server: stores, executes
  • Minion: background jobs
  • ZooKeeper + deep store
Keep it to what the following diagrams need. Unlike Iceberg, these are running servers.

Tables all the way down

  • Table
  • Partitions
  • Segments: immutable, columnar
  • Indexes per column
A segment is self-contained: its own dictionaries, forward index, other indexes, and metadata. Each index is a plug-in per column. That detail is what makes chapter 3 possible.

Min/max versus an index

  • Min/max: "which files might"
  • Inverted index: "which rows"
  • Star-tree: pre-aggregated answers
Callback to chapter 1. This is the gap Pinot was designed around.

A query, end to end

  1. Broker prunes segments
  2. Scatter to servers
  3. Servers use indexes
  4. Broker merges results
The broker prunes on metadata before any server reads a byte. Same idea as Iceberg manifests.

Offline ingestion

  1. Job builds a segment
  2. Upload to deep store
  3. Controller registers it
  4. Servers download and serve
Say the parallel out loud: build an immutable file, store it, flip the metadata. That is an Iceberg commit, written years earlier by a different team.

Realtime ingestion

  1. Servers consume a Kafka partition
  2. Rows are queryable at once
  3. Segment fills up
  4. One replica commits it
  5. It becomes immutable
Low-level consumer only, happy path only. The message to keep: even realtime data ends up as an immutable segment. Freshness comes back in the "when to use" section.

Tiered storage

  • Segments stay in S3
  • Read on demand
  • Pin hot indexes locally
  • What if the files were not ours?
StarTree feature. The bridge to chapter 3, and more than a metaphor: an External Table segment IS a tiered-storage segment on an S3 tier. The only difference is that its forward index points at Parquet somebody else wrote.
