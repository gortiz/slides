From Rust to Java bindings

Rust source → cbindgen → regex_h.h → jextract → Java bindings

Generate a C header from Rust

cargo install cbindgen
cbindgen --crate jrs-regex-panama --output regex_h.h

Output

// regex_h.h — generated by cbindgen
struct MatchResult { bool found; int32_t start; int32_t end; };

struct RegexHandle *create(
    const uint8_t *pat_ptr, uintptr_t pat_len);
bool is_match(const struct RegexHandle *handle, ...);
void destroy(struct RegexHandle *handle);
  • cbindgen reads extern "C" + #[repr(C)] → emits a C header
  • one command, no manual maintenance
  • this header IS your contract; hand it to jextract
  • struct layout (with alignment) shows up correctly

From Rust to Java bindings

Rust source → cbindgen → regex_h.h → jextract → Java bindings

Auto-generate Java bindings

jextract --output src/main/java \
  --target-package org.example.rust.generated \
  regex_h.h
// Generated by jextract — you don't write this by hand
public static MethodHandle is_match =
    LINKER.downcallHandle(
        LOOKUP.find("is_match").orElseThrow(),
        FunctionDescriptor.of(JAVA_BOOLEAN, ADDRESS, ADDRESS, JAVA_LONG));

public static StructLayout MatchResult = MemoryLayout.structLayout(
    JAVA_BOOLEAN.withName("found"),
    MemoryLayout.paddingLayout(3),   // jextract gets the padding right
    JAVA_INT.withName("start"),
    JAVA_INT.withName("end"));
  • jextract reads .h → generates the Java side
  • paddingLayout(3) appears for free — no manual math
  • all FunctionDescriptors, all VarHandles, library load
  • 🔑 you write #[repr(C)] + extern "C" + 2 commands. We did it by hand to show what's underneath. Production: use the pipeline
